# Trusted base

zwinger's guarantees hold only if the code below behaves as specified. Everything else is treated as hostile. This page states the line between the two. Its inventory is computed from the source by `tests/trusted_base.rs` (the method of gale's trusted-base gate), so the page cannot fall behind the code.

## Untrusted

zwinger assumes these may try to escape, and confines or refuses them:

- the AI agent and every process it starts, including any shell, interpreter or build tool it runs;
- WASM components the agent runs, and the runtime that runs them (wasmtime, kiln). From zwinger's side they are processes like any other;
- the profile text until the parser accepts it;
- anything in a directory the session can write, including the events directory when a write grant covers it, which is why no event is written there.

## Trusted

zwinger's own code that runs before the `exec`:

- the profile parser (`src/profile.rs`, on rivet-yaml) and its refusals;
- the planner and the carve-out and noexec checks (`src/linux.rs`, `src/pathrules.rs`), proved by Kani and, for paths of any length, by Verus;
- the seccomp program generator, proved by Kani against its classic-BPF model (`bpf_run`, itself trusted);
- the backends' system calls: `linux::sys` (close_range, seccomp, the Landlock ABI query) and `macos::enforce` (sandbox_init, fcntl). The crate denies unsafe code everywhere else (`#![deny(unsafe_code)]` in `src/lib.rs`), so the compiler holds that boundary;
- the event writer (`src/events.rs`), which runs before confinement and opens one file.

Outside zwinger's code, it trusts:

- the kernel's Landlock and seccomp, or macOS Seatbelt;
- the provers: Kani with CBMC, and Verus with Z3 and vstd's axioms;
- the Rust toolchain and the crates listed below, at the versions Cargo.lock pins.
